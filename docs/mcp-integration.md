# دمج MCP وخادم DXF (text2dxf)

## 1. تعريف MCP بإيجاز

Model Context Protocol (MCP) يحدد كيف يتواصل النموذج اللغوي مع أدوات وخدمات خارجية من خلال واجهة موحّدة (Tools). هذا يسمح للـLLM باستدعاء خادم DXF، أو قواعد بيانات، أو واجهات ويب، وكأنها دوال عادية. 

## 2. خادم DXF (text2dxf كمثال)

- تشغيل خادم MCP مسؤول عن توليد ملفات DXF.
- تسجيله في إعدادات عميل الـLLM (Claude Desktop أو Cline في VS Code).
- تعريف الأدوات (tools) التي يوفّرها، مثل:
  - إنشاء ملف DXF جديد.
  - إضافة طبقات.
  - رسم أشكال هندسية (خطوط، مستطيلات، دوائر، نصوص…).

## 3. إعدادات العميل (Client Configuration)

على مستوى عميل الـLLM:
- إضافة خادم MCP في ملف الإعدادات (config) مع عنوانه (host/port) ونوع البروتوكول.
- إعطاء اسم مفهوم للأداة مثل `cad_dxf_server` أو `draw_isolated_footing` لاستخدامه في البرومبتات.

## 4. نمط الاستخدام داخل ADAM

1. يبدأ FootingDesignEngine بالحسابات باستخدام مدخلات المستخدم.
2. بمجرد انتهاء الحسابات، يتم إنشاء كائن تصميم (FootingDesignResult) يحتوي كل الأبعاد والتسليح والقيم الحرجة.
3. LLM يستدعي أداة MCP المناسبة ويرسل لها هذا الكائن.
4. خادم DXF يحوّل الكائن إلى عمليات رسم حقيقية داخل ملف DXF ويعيد المسار أو المحتوى.
5. المسار يُضمّن في الرد للمستخدم وفي التقرير النهائي.

## 5. اعتبارات الأمان والموثوقية

- تقييد الأدوات المتاحة للـLLM إلى ما هو ضروري فقط.
- مراقبة استدعاءات الأدوات في مرحلة التطوير (Logging) للتأكد من صحة التسلسل.
- التأكد من أن ملفات DXF الناتجة تفتح بدون أخطاء في برامج CAD القياسية (AutoCAD, LibreCAD…).
