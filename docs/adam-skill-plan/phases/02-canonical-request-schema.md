## Purpose

`CanonicalDesignRequest` is the single unified input contract that ADAM accepts from any engineering client, regardless of discipline or deliverable type. Every request — whether structural, architectural, civil, or MEP — must be expressed as this object before any orchestration begins.

This contract enforces:
- No silent assumptions at intake.
- Clear discipline and intent before any domain logic runs.
- Explicit unit declaration to prevent unit-mismatch errors.
- Separation between what the engineer wants computed vs. what they want drawn vs. what they want reported.

## TypeScript Interface

```typescript
// CanonicalDesignRequest — ADAM v1.0
// All requests to ADAM must conform to this interface.

export type Discipline = 'structural' | 'architectural' | 'civil' | 'mep' | 'unknown';

export type DeliverableType =
  | 'design_and_draw'
  | 'check_and_draw'
  | 'draw_only'
  | 'check_only'
  | 'report_only';

export type LengthUnit = 'mm' | 'cm' | 'm';
export type ForceUnit  = 'kN' | 'N' | 'kip' | 'ton';
export type StressUnit = 'MPa' | 'kPa' | 'kN/m2' | 'psi';
export type AreaUnit   = 'mm2' | 'cm2' | 'm2';

export interface UnitDeclaration {
  length: LengthUnit;      // REQUIRED
  force:  ForceUnit;       // REQUIRED
  stress: StressUnit;      // REQUIRED
  area?:  AreaUnit;        // optional — inferred from length if omitted
}

export interface RequestIntent {
  deliverable_type: DeliverableType;   // REQUIRED
  element_type:     string;            // REQUIRED — e.g. 'isolated_footing'
  description?:     string;            // optional free-text context
}

export interface DesignCode {
  primary?:       string;    // e.g. 'ACI 318-19'
  supplementary?: string[];  // e.g. ['ACI 318-19 commentary', 'local amendment']
}

export interface RequiredOutputs {
  drawing:         boolean;  // REQUIRED
  report:          boolean;  // REQUIRED
  validation_log:  boolean;  // REQUIRED
  json_result?:    boolean;  // default: true
}

export interface RequestMetadata {
  project_name?: string;
  engineer?:     string;
  revision?:     string;
  notes?:        string;
  [key: string]: unknown;
}

export interface CanonicalDesignRequest {
  request_id:       string;             // REQUIRED — unique ID
  schema_version:   '1.0';              // REQUIRED — must be '1.0'
  language?:        'ar' | 'en' | 'ar-en'; // default: 'ar'
  discipline:       Discipline;          // REQUIRED
  intent:           RequestIntent;       // REQUIRED
  units:            UnitDeclaration;     // REQUIRED
  inputs:           Record<string, unknown>; // REQUIRED — domain-specific fields
  design_code?:     DesignCode;
  constraints?:     Record<string, unknown>;
  required_outputs: RequiredOutputs;     // REQUIRED
  metadata?:        RequestMetadata;
}
```

## Normalization Rules

When ADAM receives a `CanonicalDesignRequest`, the Input Normalizer applies these rules before passing to domain logic:

1. **Validate required fields** — reject or flag if any REQUIRED field is absent.
2. **Validate enum values** — reject if discipline, deliverable_type, or unit values are outside allowed enums.
3. **Detect missing domain inputs** — compare `inputs` against the domain-specific mandatory field list for the given `element_type`. Collect all missing fields.
4. **Detect conflicting inputs** — flag if values are internally inconsistent (e.g. footing_depth > foundation_depth).
5. **Infer area unit** — if `units.area` is omitted, infer from `units.length` (mm→mm2, m→m2, cm→cm2).
6. **Log all assumptions** — if any optional field is defaulted, record it in AssumptionLog.
7. **Clarification gate** — if step 3 finds missing mandatory inputs, STOP and emit structured clarification questions. Do not proceed to domain logic.

---

## Invariants (Non-Negotiable Rules)

- A request with `discipline: "unknown"` must be clarified before any domain logic runs.
- A request with `deliverable_type: "draw_only"` must include pre-computed geometry in `inputs`. ADAM does not design if `draw_only` is set.
- `required_outputs.drawing: true` requires a valid MCP drawing adapter to be available. If not available, ADAM must report this before starting.
- No domain-specific logic is invoked before the normalizer confirms all mandatory inputs for the given `element_type` are present.

## Versioning

- This document describes `CanonicalDesignRequest` version `1.0`.
- Breaking changes (new required fields, removed fields, enum changes) require a version bump.
- Additive changes (new optional fields) may be released as minor revisions.
- Schema version is checked by the orchestrator at intake. Mismatched versions are rejected with a clear error.
