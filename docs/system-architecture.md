# معمارية النظام (System Architecture)

## المكوّنات الرئيسية

1. **LLM Orchestrator**
   - مسؤول عن فهم المدخلات النصية من المهندس.
   - ينفّذ خطوات الحساب الإنشائي خطوة بخطوة.
   - يقرّر متى يستدعي أدوات MCP (مثل خادم DXF).

2. **MCP Layer**
   - طبقة وسيطة تتبع نموذج Model Context Protocol.
   - تعرّف الأدوات المتاحة للنموذج (Tools) وتنسيق الردود.

3. **CAD / DXF Server (text2dxf أو ما شابهه)**
   - يستقبل أوامر رسم عالية المستوى من LLM عبر MCP.
   - ينشئ ملف DXF منظم بالطبقات (CONC, REBAR, DIM, TEXT…).

4. **Calculation & Validation Helpers (اختياري)**
   - سكربتات أو حاسبات خارجية للتحقق من النتائج (مثلاً Retaining Wall calculators في الإصدارات القادمة).

5. **Reporting Engine (داخل LLM)**
   - يجمع النتائج في تقرير نصي منسّق (Markdown / HTML / نص عادي).

## تدفّق البيانات (عالي المستوى)

1. المهندس يقدّم مدخلات نصية لمهمة تصميم قاعدة منفصلة.
2. الـLLM يحلّل المدخلات ويحوّلها إلى نموذج بيانات داخلي (JSON: FootingDesignInput).
3. الـLLM ينفّذ خطوات الحساب:
   - مساحة القاعدة، السماكة، العزوم، القص، As، ضغط التربة…
4. بعد تثبيت الأبعاد والتسليح، الـLLM يستدعي عبر MCP خادم DXF:
   - أوامر رسم القاعدة، العمود، التسليح، الأبعاد، النصوص.
5. خادم DXF يعيد مسار/محتوى ملف DXF الجاهز.
6. الـLLM يولّد تقرير التصميم اعتماداً على نفس النموذج الحسابي.

## الحدود والتفاعلات

- **Front-end** (Cline / Claude Desktop) يتواصل فقط مع LLM Orchestrator.
- LLM Orchestrator لا يكتب الملفات مباشرة، بل يطلب من خادم DXF ذلك عبر MCP.
- أي توسيع مستقبلي (مثلاً إضافة مهمة الجدار الاستنادي) يتم بتعريف Modules إضافية وإتاحتها عبر MCP.
